# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | `int(minutes) > 10` uses whole minutes, so 09:40:01 gives 10, which is not `> 10`, and returns 0. R2 says strictly more than 10:00 *in seconds*. | Punch in 09:40:01 on a 09:30 shift: expected 10, got 0. | Compare total **seconds** (`> 600`), then floor to minutes. |
| 2 | `compute_late_minutes` | `punch_in.replace(hour=, minute=)` builds the shift start in whatever zone the datetime is in (UTC or server-local), not IST, and keeps the seconds. | Late minutes off by 5h30 when the datetime is UTC. | Build the shift start explicitly in IST from the attendance date (`shift_start_dt`). |
| 3 | `compute_late_minutes` | Ignores overnight shifts: for 22:00-06:00 a 02:00 punch-in is compared with 22:00 *today* instead of yesterday. | Overnight employee punching in at 02:00 gets a negative value, so 0 instead of 240. | Start is computed on the **attendance date** (R1), which is the previous day for early-morning overnight punch-ins. |
| 4 | `compute_work_hours` | `round()` is banker's rounding on a binary float; R4 wants half-up. Sub-second parts are not truncated. | 8h + 18s = 8.005 h should give 8.01, can give 8.0. | Integer seconds, `Decimal` division, `ROUND_HALF_UP`. Instants are truncated to seconds at the boundary. |
| 5 | `compute_overtime` | No 30-minute minimum (R3), assumes the shift ends on the punch-in date (wrong for overnight), `replace` keeps stale seconds/microseconds, and `date.fromisoformat(...)` is rebuilt from a string with a hard-coded zone. | Punch out 18:40 on a 18:30 shift returns 10 instead of 0; overnight shift returns a negative/0 value. | `shift_end_dt` adds a day for overnight shifts, floors to minutes, returns 0 below 30. |
| 6 | `GET /health` | Returns `ok` without touching MongoDB. | Stop MongoDB: still 200; the runner would start tests too early. | `ping` the server, return 503 if it fails. |
| 7 | `MongoClient` | Naive datetimes (the "decide how you handle it" trap) and the default 30 s server-selection timeout. | Mixed naive/aware arithmetic raises `TypeError`; hangs when Mongo is down. | `tz_aware=True`, 5 s timeout, one conversion layer (`to_ms` / `from_ms`). |
| 8 | `POST /employees` | Check-then-insert race and no unique index: parallel creates produce duplicates. No validation of `emp_code` format, e-mail, `joined_on`, or `shift_start == shift_end`. `created_at` is naive local time and is returned as a raw datetime instead of epoch ms. | 10 parallel POSTs: more than one 201. `joined_on: "2026-02-30"` accepted. | Unique index on `emp_code` and catch `DuplicateKeyError` (409); pydantic constraints; `created_at` is UTC and returned as epoch ms. |
| 9 | `GET /employees` | `skip = page * page_size` skips the first page; `total` counts the whole collection instead of the filter; no sort; `page`/`page_size` unbounded. | `page=1` skips the first 20 employees; `total` ignores `department`; `page_size=100000` accepted. | `(page-1)*page_size`, `count_documents(filter)`, sort by `emp_code`, `page >= 1`, `1 <= page_size <= 100`. |
| 10 | `POST /attendance/punch-in` | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError` (500, should be 404). | Punch in with an unknown `emp_code`. | `get_employee` raises 404. |
| 11 | `POST /attendance/punch-in` | `datetime.fromtimestamp(ms / 1000)` uses the **server's local zone** and a float; the `date` is therefore not the IST date (R1). `if body.punched_at` treats `0` as "missing". Seconds not truncated. | Server in UTC: punch at 01:00 IST gets yesterday's date. | `from_ms` (integer maths, UTC, truncated); `attendance_date` applies R1 incl. overnight shifts. |
| 12 | `POST /attendance/punch-in` | Check-then-insert race: two simultaneous requests can both pass the `find_one` and both insert. | 20 parallel punch-ins: several 201. | Unique index `(emp_code, date)` plus `DuplicateKeyError` to 409. No pre-check. |
| 13 | `POST /attendance/punch-in` | `status` is a free string: `ABSENT`, `LEAVE` or garbage is accepted; `punched_at` is not range-checked (seconds, floats, strings). | `status: "ABSENT"` returns 201. | `Literal["PRESENT","WFH","ON_DUTY"]`; `EpochMs` strict int in the ms range, otherwise 422. |
| 14 | `POST /attendance/punch-in` response | Returns raw datetimes and an `id` (stringified `_id`), both against the contract (instants are epoch ms, `_id` is internal). | Response contains `"id"` and ISO datetimes. | `record_out` serialises explicitly. |
| 15 | `GET /attendance` | Loads the whole collection into memory, sorts in Python, then slices. Unusable at 100k records. | Slow and memory-hungry; no index use. | `find().sort().skip().limit()` backed by indexes. |
| 16 | `GET /attendance` | Sort has no tie-break (`date` only; contract says `emp_code` ascending next); `date_from > date_to` accepted; dates and `status` not validated; `page`/`page_size` unbounded; legacy documents without `half_day` / `history` are returned as-is. | Two records on one date come back in unstable order; `status=BOGUS` returns 200. | Sort `(date desc, emp_code asc)`, strict date checks and 422 on a reversed range, `Literal` status, bounded paging, `record_out` defaults missing fields. |
| 17 | Whole app | No indexes at all. | `explain` shows COLLSCAN; list endpoint slow at scale. | `ensure_indexes()` at startup (idempotent), retried from `/health` if Mongo was not up yet. |

## Looked at and decided NOT to be a defect

* **Pydantic models ignore unknown fields.** `work_hours`, `late_minutes` etc. sent by a client are silently dropped, which is exactly what the contract asks ("if a client sends one, ignore it").
* **`compute_work_hours` argument order and sign.** `(out - in)` is correct; the problem was only rounding/truncation (#4).
* **Storing `date` as a string.** Intentional per DATA_MODEL.md: a date is not an instant; `YYYY-MM-DD` also sorts and range-queries correctly as text.
* **`doc.pop("_id")` after `insert_one`.** Fine for hiding `_id`, but replaced by `record_out` / `employee_out` so the shape is always explicit.
